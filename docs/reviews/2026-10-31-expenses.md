# Matter expenses and disbursements

Date: 31 October 2026. Checklist requirement 047; related billing requirements 050-051.

## Behavior

Staff can record a recharge or disbursement against an open, cleared matter with a date, description, GBP net amount, chosen VAT treatment and billable flag. An optional receipt points to one immutable document version. New receipt choices show the latest version of documents the viewer can already access on that matter; replacing or withdrawing a document does not silently change an existing expense reference.

Partner and fee-earner accounts need current matter-team membership. Accounts can record expenses across the firm. Compliance can read firm-wide expense records but cannot record or void them. Administrators and clients gain no new financial permissions. Receipt choices do not grant Accounts general document access.

Draft bills can select recorded billable expenses. Linked kind, description, amount and VAT treatment must match the expense; the backend verifies this independently of the disabled form controls. An expense can appear in competing drafts, but a unique issued-line source constraint permits only one issued charge. A lock serializes issue and void operations. Voiding a draft-linked expense prevents that draft being issued.

Unbilled mistakes are voided with a permanent reason and named actor; the original entry remains. Billed entries require the existing credit-note workflow. Recording an expense does not itself post money to the client/business ledgers or make a bank payment. Expense net amounts and invoice VAT use integer pence throughout.

Saving an expense uses an actor-bound request UUID. Repeating the same details returns the same entry; changing details for that request conflicts. The entry and its content-free audit commit together. A failed audit rolls back creation or voiding.

## Implementation

- Migration `0082_matter_expenses.sql`: immutable records/voids, controlled SQL functions, exact receipt references, billing source columns, locking and uniqueness.
- Migration `0083_expense_receipt_authorization.sql`: PostgreSQL rejects attaching a receipt without current document-role and matter-team access, even when a caller knows its version ID.
- `expenses.controller.ts` and `expenses.service.ts`: strict inputs, access checks, pagination, receipt choices and atomic auditing.
- `expenses-section.tsx` and `expense-form.tsx`: matter/Finance displays and record/void workflows.
- `bill-draft-form.tsx`: recorded-expense selection and explicit serialization of editable fields. Previously, editing an existing draft also sent response-only fields that the strict API correctly rejected.

The old draft-line time constraint treated null time IDs as equal, preventing multiple manual or expense lines in a draft. This migration keeps uniqueness for linked time IDs while allowing several unrelated null references. Existing issued-line time protection remains in place.
